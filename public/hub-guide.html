Reference · Shelf Hubs

How hubs actually work

A hub is the small always-online relay that lets you share a shelf with someone who runs their own separate copy of the app. This page explains what it does, the three ways you can have one, and walks through moving between them step by step.

01 · The short version

Sharing needs a middle man — this is the whole job it does

Your box keeps a full copy of a shared shelf; so does everyone else's. The hub's only jobs are: settle the order writes happened in, and pass a message along while a machine is offline. It never sees your files, never runs any AI, and never holds an API key. That's why it's cheap enough for anyone to run.

The card content on a shared shelf lives on every member's own box — the hub going away for a while doesn't lose it. What only ever lives on the hub itself: the list of who's a member, and everyone's login token for it. That's the part a hub migration (below) actually has to move.

02 · Your options

Three ways to have a hub

default

Do nothing. Every install ships pointed at one already-running shared hub — sharing works immediately, no setup.

free, not yours to control

local

Flip host a hub here on. This exact install becomes a hub too — same box, same database, nothing new to deploy.

free, only live while this box is on

cloud

Deploy shelf-hub to Railway (or anywhere else that runs Docker + Postgres) — an always-on hub you fully own.

costs whatever that hosting does

None of these change the actual sharing mechanics — a six-digit code either way. They only change which server settles the ordering and holds the membership list.

03 · Glossary

What the labels on the Shelf Hubs page mean

local hub
This install's own embedded hub — the host a hub here toggle. Off by default. Turning it on doesn't move any of your own sharing to it automatically — it just makes the option exist for whoever you hand the address to.
cloud hub
The shared Railway default every install ships pointed at, unless you change it. Free, always-on, not something you administer — there's no toggle for it because there's nothing to turn on.
which hub is active
The one hub this instance uses when you share a new shelf — set with the use cloud / use local buttons, or a custom hub's own address. Doesn't affect shelves you've already shared — see below.
the shared default
Shown next to "which hub is active" when it's currently pointed at the cloud hub specifically.
hosted on this instance
Shown next to "which hub is active" when it's currently pointed at your own local hub.
your shared shelves → "whichever hub is active"
That specific shelf has no hub of its own pinned — it just follows whatever "which hub is active" currently says. Pick local or cloud explicitly from that shelf's own dropdown to pin it there and stop it following changes above — this is how "Gift Ideas" can stay on local while "AI" stays on cloud, at the same time.
your hubs
A personal address book — hubs you've used or added, so you can switch back without re-typing a URL. Doesn't sync anywhere; it's local to this install only.

04 · Tutorial

Host locally, free, right now

  1. Set an address this box can be reached at.

    Needs PUBLIC_URL set in .env — the same requirement Drive-sharing already has, so if you can already share a shelf's Drive with someone, this is already done. It does not need to be a real, DNS-registered domain — a LAN IP (http://192.168.1.50:3016) or a Tailscale address works fine too, as long as whoever you're sharing with can actually reach it. A public domain only matters if they can't.

  2. Open Shelf Hubs → flip "host a hub here" on.

    Instant — no restart. You'll get a URL (yours ends in /relay) and a QR code.

  3. Hand that URL to whoever you want sharing through it.

    They open their own instance's Shelf Hubs page and either hit use local if you handed them this box's own address directly, or drop it into "or use a custom hub" otherwise. From then on, sharing between the two of you goes through your box specifically.

That's it — no second server, no signup, no cost. It's only reachable while this box is powered on and connected, same as your Drive already is.

05 · Tutorial

Move a local hub to an always-on cloud one

Do this once you've outgrown "only live while my box is on" — moving doesn't lose any shelf, card, or message.

  1. Deploy shelf-hub somewhere always-on.

    Railway's the easy option — a Postgres-backed Node app, deploys the same way shelf-cmd itself does. Get its database connection string once it's running.

  2. Open Shelf Hubs → "outgrown this? migrate to an always-on host."

    Shown right under your local hub's QR code while hosting is on. It pre-fills the command below with your side of the transfer already filled in.

  3. Run the command it shows you, from any machine with psql.

    Same shape either direction — this instance's data on the left, the new hub's database URL on the right:

    terminal
    $ ./scripts/migrate-hub.sh "<this instance's database url>" "<new hub's database url>" hosted_hub
  4. Back in the app, paste the new hub's address (not the database URL) and hit "repoint shelves."

    Every shelf using this local hub moves to the new one, and local hosting turns itself off — no split-brain with two "live" copies of the same data.

If someone else was also pointed at your local hub, this step only repoints your instance. They need to do the same thing on theirs — drop the new address into their own "or use a custom hub" field. There's no way to do that for them from here; it's a real limitation, not an oversight.

06 · Tutorial

Bring a cloud hub back home

If the hosting bill ever isn't worth it — the exact same steps, run in reverse.

  1. Turn "host a hub here" back on locally (step 2 of the local tutorial above, if it's currently off).
  2. Run the migrate script the other way — your cloud hub's database URL as the source, this instance's as the destination, no hosted_hub schema flag this time since the destination is the one with it:
    terminal
    $ ./scripts/migrate-hub.sh "<cloud hub's database url>" "<this instance's database url>"
  3. Repoint shelves to your local /relay address the same way, then shut the cloud deployment down whenever you're ready.

Back to the app: close this tab, or open ShelfStation. Repo: shelf-cmd · shelf-hub.
